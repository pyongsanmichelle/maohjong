# Maohjong 守備分析 基本設計書

## 1. 目的

入力済みの局面情報を使い、自分の手牌から捨てる候補について、相手別の危険度と判断理由を表示する。

本機能の危険度は放銃確率ではない。現物、筋、壁、ワンチャンス、ドラ、副露など、画面から確認できる情報を一定のルールで評価した相対的な目安とする。初期版は外部AI、有料API、通信処理を使わず、端末内の純粋なDartで完結させる。

## 2. 対象範囲

### 2.1 含めるもの

- 上家、対面、下家から分析対象を1人選ぶ操作
- 自分の手牌にある牌種ごとの危険度評価
- 「安全」「注意」「危険」の3段階表示
- 0から100までの並び替え用スコア
- 現物、筋、壁、ワンチャンス、ドラ、副露を使った理由表示
- 手牌順と危険度順の切り替え
- 入力局面の変更に追従する再分析
- 同じ局面から常に同じ結果を返す決定的な判定

### 2.2 含めないもの

- 正確な放銃確率や和了率の算出
- 相手の待ち牌、手役、打点の断定
- 手牌読み、押し引き判断、期待値計算
- リーチ宣言位置を利用した宣言後現物の判定
- 赤ドラと、カン種別ごとの個別な危険度補正
- 複数相手を合算した総合危険度
- 音声案内、カメラ入力、外部AI API

## 3. 前提と注意表示

- 分析対象は自分以外の3人とする。
- 分析対象の河は捨てた順番を保持しているものとして扱う。
- 鳴かれて河から取り除かれた牌も、その牌を捨てた人の捨て牌履歴に含める。
- 「安全」は入力済み情報に基づく分類であり、放銃しないことを保証しない。
- 筋、壁、ワンチャンス、副露による推測は危険度を上下させる参考情報であり、単独で安全を断定しない。
- 入力漏れや入力誤りがある場合、分析結果も不正確になる。

画面には常に「危険度は入力済み情報に基づく目安です」と表示する。

## 4. 利用者操作

1. 対局入力を開始し、手牌、各家の河、ドラ表示牌、副露を入力する。
2. 「守備分析」を押して分析画面を開く。
3. 上家、対面、下家のタブから分析対象を選ぶ。
4. 自分の手牌にある牌種ごとの危険度を確認する。
5. 牌をタップして、危険度が上下した理由を確認する。
6. 必要に応じて「手牌順」と「危険度順」を切り替える。
7. 局面入力へ戻って牌を修正した場合、次に分析画面を表示した時点で再計算する。

## 5. 画面設計

局面入力画面の「守備分析」ボタンから別画面を開く。局面入力画面の縦方向を圧迫せず、分析結果を最大14種類まで見やすく配置する。

```text
┌──────────────────────────────┐
│ 守備分析                      │
│ [上家] [対面] [下家]          │
│ 危険度は入力済み情報に基づく目安 │
│ [手牌順] [危険度順]            │
├──────────────────────────────┤
│ [1萬 安全  0] [2萬 注意 42]    │
│ [5筒 危険 78] [東  注意 55]    │
│          最大7枚 × 2行         │
├──────────────────────────────┤
│ 選択: 5筒                     │
│ ・ドラのため危険度が上昇       │
│ ・対象相手の河に筋情報がない    │
│ ・強い安全材料が見つからない    │
└──────────────────────────────┘
```

### 5.1 表示規則

- 同じ牌を複数持っていても、分析カードは牌種ごとに1件だけ表示する。
- 分析カードには牌、3段階の危険度、スコアを表示する。
- 色だけに依存せず、「安全」「注意」「危険」の文字を併記する。
- 初期表示は手牌の標準順とする。
- 危険度順ではスコアの高い牌を先頭にし、同点は牌の標準順にする。
- 牌カードは端末幅から幅を算出し、360px幅では最大7枚を横一列に表示する。
- 理由は重要度順に表示し、同じ理由を重複表示しない。

## 6. ドメイン設計

### 6.1 Opponent

分析対象を表す列挙型。`upper`、`across`、`lower`を持ち、既存の河を表す`InputTarget`との対応付けを1か所に集約する。自分は分析対象に含めない。

### 6.2 DangerLevel

利用者向けの3段階表示を表す。

- `safe`: 安全。スコア0から25。
- `caution`: 注意。スコア26から59。
- `danger`: 危険。スコア60から100。

境界値は定数として管理し、UIへ直接記述しない。

### 6.3 DangerReasonCode

判定理由を機械的に識別する列挙型。初期版では次を持つ。

- `genbutsu`: 対象相手の捨て牌履歴に同じ牌がある。
- `allCopiesVisible`: 同じ牌が局面全体で4枚見えている。
- `fullSuji`: 両側の筋情報がそろっている。
- `suji`: 片側または端側の筋情報がある。
- `kabe`: 両面待ちを構成する隣接牌が4枚見えている。
- `oneChance`: 両面待ちを構成する隣接牌が3枚見えている。
- `dora`: ドラに該当する。
- `openSuitPressure`: 対象相手の同一色の副露が2組以上ある。
- `honorVisibility`: 字牌の見えている枚数による補正がある。
- `noStrongEvidence`: 強い安全材料が見つからない。

理由コードと日本語表示文は分離し、テストでは理由コードと根拠値を検証する。

### 6.4 DangerReason

1件の判定理由を表す不変オブジェクト。

- `code`: 理由コード
- `scoreDelta`: スコアへ加算した値
- `relatedTiles`: 判定根拠になった牌の不変リスト
- `evidenceCount`: 見えている枚数やドラの重複数などの根拠値。不要な理由では`null`
- `priority`: 表示順

利用者向けの日本語説明文は保持せず、プレゼンテーション層の`DangerReasonFormatter`が理由コードと根拠値から生成する。

### 6.5 DangerAssessment

1種類の牌に対する評価結果を表す不変オブジェクト。

- `tile`: 評価対象の牌
- `opponent`: 分析対象の相手
- `score`: 0から100までの整数
- `level`: 3段階の危険度
- `reasons`: 判定理由の不変リスト

### 6.6 DangerAnalyzer

`GameSituation`と`Opponent`を受け取り、自分の手牌にある牌種ごとの`DangerAssessment`を返す純粋なドメインサービスとする。

- FlutterのWidget、BuildContext、状態管理へ依存しない。
- 入力した`GameSituation`を変更しない。
- 通信、時刻、乱数を使わない。
- 同じ入力には同じ結果と並び順を返す。
- スコアの重み、しきい値、理由の優先度は定数へ集約する。

## 7. 判定に使う局面情報

### 7.1 見えている牌

既存の`GameSituation.count(tile)`を使い、次の領域を合算する。

- 自分の手牌
- 自分、上家、対面、下家の河
- ドラ表示牌
- 全員の副露・カン

### 7.2 対象相手の捨て牌履歴

対象相手の現在の河に加え、次の副露の`calledTile`を履歴へ戻して扱う。

- `Meld.fromRiver`が対象相手の河と一致する副露

これにより、他家に鳴かれて河から消えた捨て牌も現物・筋判定から失われない。

### 7.3 ドラ

ドラ表示牌から実際のドラを求める処理を共通関数として分離する。

- 数牌は1から9を循環する。9の次は1。
- 風牌は東、南、西、北を循環する。
- 三元牌は白、發、中を循環する。
- ドラ表示牌が複数ある場合はすべて評価し、同じドラが重複した場合は重複数を危険度へ反映する。

## 8. 判定ルール

### 8.1 基本方針

- 数牌の初期スコアを50、字牌の初期スコアを55とする。
- 各ルールの増減値を加算し、最後に0から100へ丸める。
- 明確な安全材料は通常の加減算より優先する。
- 初期値と重みは放銃確率ではなく、牌同士を相対比較するための値とする。

### 8.2 優先判定

次のいずれかを満たす場合はスコアを0にし、それ以外の加点を行わない。

1. 対象相手の捨て牌履歴に同じ牌がある現物。
2. 同じ牌が局面全体で4枚見えており、対象相手が同牌を持ち得ない。

### 8.3 筋

数牌だけを対象に、対象相手の捨て牌履歴から筋情報を評価する。

- 1、2、3は、それぞれ4、5、6が履歴にあれば筋として減点する。
- 7、8、9は、それぞれ4、5、6が履歴にあれば筋として減点する。
- 4は1と7、5は2と8、6は3と9の両方が履歴にあれば両筋として大きく減点する。
- 4、5、6で片側だけが履歴にある場合は片筋として小さく減点する。
- 筋は単騎、シャンポン、カンチャン、ペンチャンを否定しないため、優先判定にはしない。

初期重みは、両筋を-20、筋・片筋を-10とする。

### 8.4 壁とワンチャンス

候補牌を待ちに含む両面形ごとに、その形に必要な隣接牌の見えている枚数を確認する。

- 必要な隣接牌のいずれかが4枚見えている両面形は、壁により成立しない形として扱う。
- 必要な隣接牌のいずれかが3枚見えている両面形は、ワンチャンスとして扱う。
- 候補牌が複数の両面形に関係する場合は、成立しない形の数を考慮する。
- 壁やワンチャンスだけで安全を断定しない。

初期重みは、関係する全両面形が壁で否定された場合を-20、一部だけの場合を-10、ワンチャンスを-5とする。壁とワンチャンスが同じ形で成立する場合は壁だけを採用する。

### 8.5 字牌の見えている枚数

字牌は筋、壁、ワンチャンスの対象外とし、局面全体で見えている同牌の枚数を理由に含める。

- 3枚見えている場合は-20。
- 2枚見えている場合は-10。
- 1枚以下の場合は補正しない。
- 4枚見えている場合は優先判定を適用する。

国士無双などの例外があるため、3枚見えでもスコア0にはしない。

### 8.6 ドラ

- 候補牌がドラの場合、ドラ1枚につき+15する。
- 複数のドラ表示牌が同じドラを示す場合は重複して加点する。
- ドラであることだけを理由に待ち牌と断定しない。

### 8.7 副露による色の偏り

- 対象相手が同じ数牌の色で2組以上副露している場合、その色の候補牌へ+10する。
- 字牌の副露は色の組数へ含めない。
- 清一色や混一色を断定せず、「同色の副露が複数あるため注意」という参考理由だけを表示する。
- 初期版では異なる色の牌を安全側へ補正しない。

### 8.8 強い情報がない場合

優先判定、筋、壁、ワンチャンス、字牌の枚数、ドラ、副露のいずれにも該当しない場合は、`noStrongEvidence`を理由として追加する。スコアは変更しない。

## 9. 判定順序

1. 手牌から重複を除き、標準順の候補牌を作る。
2. 対象相手の捨て牌履歴を作る。
3. 現物と4枚見えの優先判定を行う。
4. 数牌は筋、壁、ワンチャンスを評価する。
5. 字牌は見えている枚数を評価する。
6. ドラを評価する。
7. 対象相手の副露による色の偏りを評価する。
8. 理由がない場合は強い情報なしを追加する。
9. スコアを0から100へ丸め、危険度へ変換する。
10. 指定された表示順で並べる。

## 10. アーキテクチャ

```text
presentation
  SituationInputPage       守備分析画面を開く
  DangerAnalysisPage       相手・並び順の選択と結果表示
  DangerTileCard           牌、危険度、スコアの表示
  DangerReasonPanel        選択した牌の理由表示
  DangerReasonFormatter    理由コードと根拠値の日本語表示変換
application
  AnalyzeDangerUseCase     画面から分析を呼び出す窓口
domain
  DangerAnalyzer           ルールベースの純粋な判定
  DangerAssessment         牌ごとの評価結果
  DangerReason             判定理由
  Opponent / DangerLevel   分析対象と表示区分
  GameSituation / Tile     既存の局面データ
```

`DangerAnalysisPage`は`GameSituation`を受け取り、相手または並び順が変わった時に`AnalyzeDangerUseCase`を呼ぶ。ドメイン層は画面表示用の色やWidgetを返さない。

## 11. エラーと空状態

- 手牌が空の場合は「手牌を入力してください」と表示し、結果一覧を表示しない。
- 選択した相手の河や副露が空でも分析は実行し、「相手の捨て牌情報が未入力です」と注意表示する。
- 局面内に同じ牌が5枚以上ある不正データを受け取った場合は、分析せず入力修正を促す。
- 一部の情報がない場合もアプリを停止せず、利用可能な情報だけで結果を返す。

## 12. テスト方針

### 12.1 ドメインテスト

- 手牌の同じ牌が1件の評価へまとめられる。
- 上家、対面、下家で参照する河が切り替わる。
- 対象相手の河にある牌が現物としてスコア0になる。
- 他家に鳴かれて河から消えた牌も対象相手の現物・筋判定へ使われる。
- 同じ牌が4枚見えている場合にスコア0になる。
- 端側の筋、片筋、両筋が別々の重みで評価される。
- 壁とワンチャンスが別々に評価され、同じ形では重複加算されない。
- 字牌の見えている枚数が評価へ反映される。
- 数牌、風牌、三元牌のドラが正しく循環する。
- 複数ドラ表示牌と重複ドラが評価へ反映される。
- 同色の副露が2組以上ある場合だけ色の偏りが加点される。
- スコアが0から100の範囲へ丸められる。
- 境界値25、26、59、60で危険度が正しく変わる。
- 同じ局面では評価、理由順、表示順が常に同じになる。
- 分析前後で`GameSituation`が変更されない。

### 12.2 ウィジェットテスト

- 3人の相手を切り替えられる。
- 手牌順と危険度順を切り替えられる。
- 牌カードに危険度の文字とスコアが表示される。
- 牌カードを選ぶと理由が表示される。
- 注意文と情報不足時の表示がある。
- 360px幅で最大7枚のカードが横一列に収まる。
- 局面を変更して再度開くと分析結果が更新される。
