# Maohjong 対局中コンパクトアクションバー 基本設計書

## 1. 目的

対局開始後に表示する操作群を、縦方向の表示領域を圧迫しない固定高さのアクションバーへ再構成する。

現在の文字付きボタンを`Wrap`で並べる構成では、小型端末や文字拡大時に複数行へ増え、卓、入力状態、牌パレット、固定手牌を含む`Column`の利用可能高を超えて`RenderFlex overflow`が発生する。本対応では、利用頻度と局面依存性に基づいて操作を整理し、すべての既存操作へ到達できることと、360 × 640の縦画面でも主要局面が隠れないことを両立する。

## 2. 対象範囲

### 2.1 含めるもの

- 対局開始後の`MatchActionBar`の固定高さ・1行化
- 主要操作のアイコン中心表示
- 利用頻度の低い操作をまとめる「その他」メニュー
- 鳴きと自分のカンの既存表示条件の維持
- 各操作のTooltip、日本語Semantics、最小タップ領域
- 小型端末と文字拡大時のoverflow防止
- 鳴き操作へ実際に到達できることを確認するWidgetテスト
- 既存レイアウトの高さ配分の調整

### 2.2 含めないもの

- チー、ポン、カンの成立条件や手番遷移の変更
- 取り消し、局面補正、追加ドラ、局終了、分析の業務ロジック変更
- 卓、河、副露、ドラ、固定手牌の位置関係変更
- 開始前画面の変更
- 点数計算、親の連荘、リーチ入力
- 危険牌および相手の狙い役・待ち牌の分析規則変更

## 3. 現状と課題

`SituationInputPage._buildActionControls`は、次の文字付きボタンと案内文を1つの`Wrap`へ配置している。

- 取り消し
- チー・ポン・カン
- 局面補正
- ドラ追加
- 自分のカン
- 局終了
- 相手分析
- 設定に戻る
- 次に行う入力の案内

操作数や文字幅に応じて`Wrap`の高さが増える一方、卓領域には固定の最小高さがあり、牌パレットも操作に必要な領域を持つ。そのため、特に360 × 640の縦画面や文字拡大時に、開始後画面全体の高さ制約を満たせない。

また、鳴き操作は直前打牌後、自分のカンは成立候補がある自分の手番だけに現れるため、ボタン出現時にレイアウト高が変わる。操作ボタンの存在確認だけでは、画面内で実際にタップ可能かを保証できない。

## 4. 設計原則

### 4.1 操作の優先順位

対局進行中に即時性が高い操作をアクションバーへ常時または条件付きで表示し、補助・管理操作は「その他」メニューへ移す。

| 区分 | 操作 | 表示方針 |
|---|---|---|
| 主要 | 取り消し | 常時表示。履歴がない場合は無効 |
| 文脈依存 | チー・ポン・カン | 直前打牌が存在する場合だけ表示 |
| 文脈依存 | 自分のカン | 自分の打牌可能手番で候補がある場合だけ表示 |
| 主要 | 局終了 | 常時表示 |
| 補助 | 局面補正 | 「その他」メニュー |
| 補助 | ドラ追加 | 「その他」メニュー |
| 補助 | 相手分析 | 「その他」メニュー |
| 管理 | 設定に戻る | 「その他」メニュー内で他項目と区切って表示 |

「その他」メニュー自体は対局開始後に常時表示する。メニューへ移した操作も削除せず、2タップ以内で到達可能にする。

### 4.2 高さを変えない

`MatchActionBar`は`Wrap`を使用せず、固定高さの1行`Row`とする。文脈依存操作の出現・消失によってバーの高さを変えない。操作数が最大になっても横方向へ収まるよう、バー上の操作はアイコンを主体とする。

画面幅不足を`FittedBox`による一括縮小で解決しない。アイコンとタップ領域の視認性を維持したまま、操作の優先順位で表示場所を分ける。

### 4.3 状態案内を重複させない

現在の入力状態は既存の`matchInputStatus`を唯一の画面上案内とする。アクションバー内に「次に選択する牌」などの案内文は置かず、バーの高さと幅を操作のために使用する。

## 5. 画面構成

### 5.1 標準状態

```text
┌────────────────────────────────┐
│ 卓・河・副露・ドラ              │
├────────────────────────────────┤
│ 対局入力中：下家の河を選択       │
├────────────────────────────────┤
│ [戻す] [局終了]        [その他] │  固定高さ・1行
├────────────────────────────────┤
│ 牌を選ぶ                         │
│ 牌パレット（内部スクロール）     │
├────────────────────────────────┤
│ 自分の固定手牌                   │
└────────────────────────────────┘
```

### 5.2 直前打牌がある状態

```text
│ [戻す] [鳴き] [局終了]  [その他] │
```

### 5.3 自分のカンが可能な状態

```text
│ [戻す] [カン] [局終了]  [その他] │
```

鳴きと自分のカンの条件が同時に成立する場合も、両方を省略せず同じ1行へ表示する。最大構成は、取り消し、鳴き、自分のカン、局終了、その他の5操作とし、各操作が360 logical pixelsの幅へ収まるメトリクスを使用する。

## 6. コンポーネント設計

### 6.1 MatchActionBar

表示専用Widgetとして切り出し、次の値を受け取る。

- 取り消し可否
- 鳴き操作の表示可否とコールバック
- 自分のカン操作の表示可否とコールバック
- 局終了コールバック
- 局面補正コールバック
- 追加ドラコールバック
- 相手分析コールバック
- 設定に戻るコールバック

`MatchActionBar`は`GameSituation`、`MatchInputFlow`、`SituationEditor`を直接参照しない。表示条件や有効状態は`SituationInputPage`が既存の状態から算出して渡す。

### 6.2 主要アクション

主要アクションは`IconButton`または同等のアイコン中心部品とする。

- 取り消し: `Icons.undo`
- 鳴き: `Icons.call_split`
- 自分のカン: `Icons.view_module`
- 局終了: `Icons.sports_score`
- その他: `Icons.more_vert`

アイコンだけで意味を推測させず、各操作にTooltipとSemanticsを設定する。文脈依存操作には色またはコンテナを使って注意を向けてもよいが、表示条件や意味を色だけで表現しない。

### 6.3 その他メニュー

`PopupMenuButton`または同等のMaterialメニューを使用し、次の順で表示する。

1. 局面補正
2. ドラ追加
3. 相手分析
4. 区切り
5. 設定に戻る

メニュー項目は文字とアイコンを併記する。文字倍率により全項目が同時表示できない場合は、メニュー内部のスクロールで到達可能にする。

### 6.4 SituationInputPage

既存条件を変更せず、`MatchActionBar`へ次を渡す。

- `canUndo = SituationEditor.canUndo`
- `showCall = MatchInputFlow.lastDiscard != null`
- `showSelfKan = isOwnDiscardTurn && MatchInputFlow.canOwnDiscard && SituationEditor.selfKanOptions.isNotEmpty`
- 各既存ダイアログ、画面遷移、編集処理のコールバック

ボタン移動を理由に、鳴き・カン・局終了などの処理をWidgetへ複製しない。

## 7. レイアウトとレスポンシブ設計

### 7.1 アクションバー

- 高さはMaterialの最小タップ領域を満たす48 logical pixels以上とする
- 上下余白を含むバー全体の高さを一定にする
- `Row`内では主要操作を左から優先順に並べ、「その他」を右端へ配置する
- 各操作の最小タップ領域は48 × 48 logical pixelsを維持する
- 表示中の主要操作数にかかわらず、縦方向へ折り返さない
- 画面端と固定手牌のSafeAreaを考慮する

### 7.2 開始後画面の高さ配分

開始後画面は、次の優先順位で高さを配分する。

1. `PersistentHand`を`Scaffold.bottomNavigationBar`へ固定
2. `CompactRoundStatus`と`matchInputStatus`を内容に応じた最小高さで表示
3. `MatchActionBar`へ固定高さを確保
4. `TableBoard`へ残り高のうち優先領域を割り当てる
5. `TilePalettePanel`へ操作可能な最小高を確保し、内部だけをスクロール可能にする

卓の高さを固定下限だけで決めて全体を超過させない。`LayoutBuilder`で利用可能高から固定領域を差し引き、卓と牌パレットへ制約内の高さを配分する。極端に高さが不足する場合も、アクションバーを複数行にせず牌パレットの内部スクロール量を増やす。

### 7.3 検証条件

少なくとも次を検証する。

- 360 × 640、文字倍率1.0
- 360 × 640、文字倍率1.5
- 360 × 640、文字倍率2.0におけるアクションバーとメニュー
- 412 × 915、文字倍率1.0

文字倍率2.0では、アイコン中心のアクションバーは1行を維持し、Tooltipとメニューの文字は欠けずに読めることを確認する。

## 8. アクセシビリティ

- 各主要操作に日本語の`Tooltip.message`を設定する
- 各主要操作に`Semantics(button: true, label: ..., enabled: ...)`を設定する
- 取り消し無効時も操作の意味と無効状態を支援技術へ伝える
- 「その他」ボタンのSemanticsラベルは「その他の対局操作」とする
- メニュー項目は日本語の可視ラベルを持つ
- タップ領域をアイコンの描画サイズと同じまで縮小しない
- キーボードまたは支援技術によるフォーカス順を、画面上の優先順と一致させる

## 9. 安定したWidget Key

既存テストとの互換性を優先し、操作の表示場所が変わっても次のKeyを維持する。

- `matchActionBar`
- `undoButton`
- `callButton`
- `selfKanButton`
- `roundEndButton`
- `kanCorrectionButton`
- `addDoraButton`
- `dangerAnalysisButton`
- `returnToSetupButton`

次を追加する。

- `matchMoreMenuButton`

メニューへ移した操作は、メニューを開いた後に既存Keyで取得可能にする。

## 10. 状態と操作フロー

### 10.1 鳴き

1. 他家または自分の河へ打牌が登録される
2. `lastDiscard`が存在するため`callButton`が現れる
3. 利用者が鳴きボタンを押す
4. 既存の鳴きダイアログでチー、ポン、カンを選択する
5. 既存の候補選択と確定処理を行う
6. 副露、河、手番、嶺上牌待ちを既存規則どおり更新する

バーの高さは、手順1の前後で変化しない。

### 10.2 自分のカン

1. 自分の打牌可能手番かつカン候補が存在する
2. `selfKanButton`が現れる
3. 利用者がカンボタンを押す
4. 既存ダイアログで暗槓または加槓候補を選択して確定する
5. 必須のカンドラ表示牌選択を開く
6. 表示牌を1枚追加してから、既存規則どおり嶺上牌待ちへ進む

暗槓、加槓、大明槓はいずれも、カン成立直後に新しいドラ表示牌を入力し、その後に嶺上牌を入力する。`MatchInputFlow.kanDoraPending`の間は通常のツモ・打牌を受け付けない。カンを取り消した場合は、そのカンによって末尾へ追加したドラ表示牌も取り除く。

### 10.3 その他メニュー

1. 利用者が「その他」を押す
2. メニューから操作を選ぶ
3. メニューを閉じる
4. 既存のダイアログまたは画面遷移を開始する

メニューを閉じただけでは局面や進行状態を変更しない。

## 11. テスト方針

### 11.1 MatchActionBar単体Widgetテスト

- 最小状態で取り消し、局終了、その他が1行に表示される
- 取り消し履歴がない場合に取り消しが無効になる
- 鳴き可のときだけ`callButton`が表示される
- 自分のカン可のときだけ`selfKanButton`が表示される
- 鳴きと自分のカンを同時表示しても高さが変わらない
- その他メニューから局面補正、ドラ追加、相手分析、設定に戻るへ到達できる
- 各主要操作にTooltipと日本語Semanticsがある
- 主要操作のタップ領域が48 × 48以上である

### 11.2 開始後画面Widgetテスト

- 360 × 640で`RenderFlex overflow`を含むレイアウト例外が発生しない
- 360 × 640、文字倍率1.5でもレイアウト例外が発生しない
- 文字倍率2.0でもアクションバーが1行を維持し、その他メニューを操作できる
- `matchActionBar`の高さが文脈依存操作の出現前後で変わらない
- 卓、入力状態、牌パレット、固定手牌がアクションバーに隠れない
- 主要操作が画面内にあり、`hitTestable`である
- その他メニューを開いた後、各補助操作が画面内で選択できる

### 11.3 鳴き操作の回帰テスト

少なくともポンの一連の操作をWidgetテストで確認する。

1. 対局を開始する
2. 他家の打牌を登録する
3. 画面内の`callButton`を押す
4. ポンと使用牌を選択して確定する
5. 所有者の副露領域にポンが表示される
6. 河から対象牌が鳴かれた状態になり、手番が既存規則どおり移る

チー、ポン、カンの成立条件と状態遷移そのものは既存ドメインテストを維持する。UIテストでは、ボタンが存在するだけでなく実際に押せることを確認する。

### 11.4 回帰テスト

- 自分のカンと嶺上牌待ち
- 暗槓、加槓、大明槓後のドラ表示牌入力順
- カン取消時の追加ドラ取り消し
- 取り消しと副露取り消し
- 局面補正と追加ドラ
- ツモ、ロン、流局による局終了
- 守備分析と相手分析への遷移
- 設定に戻ってからの再開
- 固定手牌の打牌、危険率、長押し理由表示

## 12. 実装方針

1. 現在の`_buildActionControls`から開始前の開始ボタンと開始後操作を分離する
2. 表示専用の`MatchActionBar`を追加する
3. 主要操作をアイコン中心の1行へ移す
4. 補助操作をその他メニューへ移す
5. 重複する入力案内を削除し、`matchInputStatus`へ集約する
6. `StartedTableLayout`と牌パレットの高さ配分を制約ベースへ調整する
7. 単体・レイアウト・鳴き操作のWidgetテストを追加する
8. エミュレータで小型縦画面と文字拡大時を確認する

新規・変更するDartのクラス、メソッド、State内の意味ある非公開UI構築処理には、日本語Dartdocを付与する。

- 360 × 640の縦画面でoverflowが発生しない
- 文字倍率1.5で画面全体にoverflowが発生しない
- 文字倍率2.0でアクションバーとその他メニューを操作できる

- Tooltip、Semantics、48 × 48以上のタップ領域を備える
