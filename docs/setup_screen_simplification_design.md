# Maohjong 対局開始前画面の簡略化 基本設計書

## 1. 目的

対局開始前の画面を、開始に必要な情報だけを迷わず入力できる構成へ簡略化する。

新しい半荘は東1局・1巡目から始まるため、場・局・巡目の編集欄を廃止する。手牌と最初のドラ表示牌はタブで切り替えず同一画面へ常時表示し、開始前の操作を「親の位置」「手牌」「最初のドラ表示牌」「開始」に限定する。

開始時点のカン登録と汎用の取り消しは開始後へ移し、既存の進行、枚数制約、カン、追加ドラ、危険牌・役待ち分析には影響を与えない。

## 2. 対象範囲

### 2.1 含めるもの

- 開始前の場風、局番号、巡目の編集UIを削除
- 新しい半荘を東1局・1巡目で初期化
- 自動進行した次局では現在の場・局を表示専用で案内
- 手牌と最初のドラ表示牌を同一画面へ常時表示
- タブ以外の明確な操作による手牌・ドラ入力先の切り替え
- 開始前のカン登録ボタンと取り消しボタンを削除
- 開始後のカン登録・補正、追加ドラ、取り消し操作
- 南4局終了後に東1局へ戻る「新しい対局」操作
- 既存Widgetテストの更新と回帰テスト

### 2.2 含めないもの

- 親位置選択の廃止または自動判定
- 東1局以外から半荘を途中開始する機能
- 本場、供託、点数、親の連荘
- 開始後の卓レイアウトの再変更
- 危険牌、役候補、待ち候補の判定変更
- カメラ入力、音声入力、外部AI

## 3. 基本方針

1. 初期画面では「いま何を入力するか」を一つに絞る。
2. 手牌とドラは常に見える状態にし、タブで存在を隠さない。
3. 選択状態は強調枠、背景色、「入力中」の文字を併用する。
4. 開始前の誤入力は牌そのもののタップ削除で訂正する。
5. 開始後の時系列操作は既存の取り消しで訂正する。
6. 場・局・巡目はドメインの進行状態を正とする。
7. 表示を簡略化しても既存の入力制約を緩めない。

## 4. 画面状態

### 4.1 NewMatchSetup

アプリ起動直後、または半荘終了後に「新しい対局」を押した状態。

- `RoundProgress`: 東場・1局・1巡目・残りツモ69回
- 手牌、ドラ、河、副露、公開アクション履歴: 空
- 親: 自分を初期値として利用者が変更可能
- 初期入力対象: 手牌

### 4.2 NextRoundSetup

ツモ、ロン、流局で次局へ自動進行した後の準備状態。

- 場・局は`RoundProgress.advanceRound()`の結果を保持
- 巡目は1、残りツモは69回
- 親は既存の簡易進行に従って次の位置へ移動
- 前局の牌情報は初期化済み
- 場・局・巡目は表示のみで編集不可
- 利用者は新しい手牌と最初のドラを入力して開始

### 4.3 InMatch

「開始」を押した後の既存対局入力状態。

- コンパクトな局情報、卓、固定手牌を表示
- 取り消し、鳴き、カン、局終了、相手分析を表示
- 開始時点のカン補正と追加ドラへ到達可能

### 4.4 MatchFinished

南4局が終了した状態。

- 開始ボタンの代わりに「新しい対局」を表示
- 押下時に東1局・1巡目へ初期化して`NewMatchSetup`へ移る
- 場・局・巡目の編集欄は表示しない

## 5. 利用者フロー

### 5.1 新しい半荘

1. 表示専用の「東1局・1巡目」を確認する。
2. 親の位置を選択する。
3. 初期選択されている手牌へ牌を追加する。
4. 「最初のドラ表示牌」領域をタップして入力対象を切り替える。
5. 牌パレットからドラ表示牌を1枚選ぶ。
6. 誤入力は対象の牌を直接タップして削除し、選び直す。
7. 開始条件を満たすと有効になる「開始」を押す。
8. 親の位置から既存の河入力を開始する。

### 5.2 次局

1. 局終了後、`NextRoundSetup`へ自動遷移する。
2. 自動進行した場・局と親位置を確認する。
3. 新しい手牌と最初のドラを入力する。
4. 「開始」を押して次局を開始する。

### 5.3 開始時点のカン補正

1. 「開始」を押して`InMatch`へ移る。
2. 開始後の「開始時点のカン」または「局面補正」を開く。
3. プレイヤー、牌、明槓・暗槓・加槓を選ぶ。
4. 既存`SituationEditor.registerSetupKan`の制約で登録する。
5. カンに対応する追加ドラを専用の牌選択から登録する。
6. 誤登録は対象の副露をタップして取り消す。

これは通常の鳴きや手番中のカンと区別し、手番を移動させない「現在局面の補正」として扱う。

## 6. 開始前画面

```text
┌────────────────────────────────┐
│ Maohjong                        │
│ 東1局・1巡目                    │
│ 親 [自分] [下家] [対面] [上家]  │
├────────────────────────────────┤
│ 自分の手牌               入力中 │
│ [牌][牌][牌][牌] ...            │
│ 3/14枚                          │
├────────────────────────────────┤
│ 最初のドラ表示牌                │
│ [未選択]                        │
├────────────────────────────────┤
│ 牌を選ぶ                        │
│ 1萬 ... 9萬                     │
│ 1筒 ... 9筒                     │
│ 1索 ... 9索                     │
│ 東 南 西 北 白 發 中             │
├────────────────────────────────┤
│ 開始にはドラ表示牌が必要です     │
│                         [開始]  │
└────────────────────────────────┘
```

### 6.1 表示するもの

- 現在の場・局・巡目の短い表示
- 親位置の選択
- 自分の手牌領域
- 最初のドラ表示牌領域
- 共通の牌パレット
- 開始条件の不足内容
- 開始ボタン

### 6.2 表示しないもの

- 東場・南場の選択
- 局番号・巡目のドロップダウン
- 残りツモ回数の詳細
- 手牌、自分、上家、対面、下家、ドラのタブ
- 河と副露
- 開始時点のカン、取り消し
- 局終了、鳴き、カン、相手分析、設定に戻る

### 6.3 入力対象

開始前に選べる入力対象は`InputTarget.hand`と`InputTarget.doraIndicators`だけとする。両領域を常時表示し、領域全体のタップで切り替える。

選択中の領域には強調枠、背景色、「入力中」ラベル、Semanticsの選択状態を付ける。牌パレットは選択中の領域へ牌タップを通知し、タブのインデックスを使用しない。

### 6.4 直接削除

- 手牌の牌をタップするとその1枚を削除する。
- ドラ表示牌をタップすると削除する。
- 削除後も入力対象を維持する。
- 同じ牌が複数ある場合もタップした位置だけを削除する。
- 開始前の汎用「取り消し」は表示しない。

### 6.5 最初のドラ表示牌

- 開始前は0枚または1枚だけ保持できる。
- 1枚選択済みなら追加を無効にし、直接削除を案内する。
- 手牌との合計が同一牌4枚を超えなければ同じ牌も選択できる。
- 2枚目以降は開始後の追加ドラ操作で登録する。

## 7. 開始条件

### 7.1 MatchSetupValidation

開始可否を単一の`bool`だけでUIへ渡さず、不足理由を提示できる結果を定義する。

- `canStart`: 開始可能か
- `issues`: `SetupValidationIssue`の不変リスト

### 7.2 SetupValidationIssue

- `handEmpty`: 手牌が未入力
- `doraMissing`: 最初のドラが未入力
- `tooManyInitialDora`: 開始前のドラが2枚以上
- `handLimitExceeded`: 親・子に応じた手牌上限超過
- `matchFinished`: 新しい対局への初期化が必要
- `invalidVisibleTileCount`: 同一牌が5枚以上

UIだけが理由コードを日本語へ変換する。

### 7.3 開始ボタン

- `canStart == true`のときだけ有効にする。
- 無効時は先頭の不足理由をボタン付近へ持続表示する。
- `start()`は現在の場・局を維持し、毎回東1局へ戻さない。
- 新規半荘は事前に`resetForNewMatch()`されているため東1局となる。
- 次局準備では自動進行済みの場・局を維持する。
- 開始時に従来どおり編集履歴を消し、公開アクション履歴を初期化する。

## 8. 局進行

### 8.1 初期値

`RoundProgress`の既存デフォルトを唯一の初期値とする。

- `roundWind = RoundWind.east`
- `kyoku = 1`
- `turn = 1`
- `remainingDraws = 69`

Widgetへ同じ初期値を重複定義しない。

### 8.2 次局

- 4打牌ごとの巡目更新を維持する。
- ツモ、ロン、流局後は既存`advanceRound()`を使う。
- 次局では巡目1、残り69回へ戻る。
- 東4局後は南1局、南4局後は`MatchFinished`へ進む。

### 8.3 新しい対局

`RoundProgress.resetForNewMatch()`を追加し、東場、1局、1巡目、残り69回、巡目内打牌数0、半荘終了状態`false`を一括初期化する。

`MatchInputFlow.resetForNewMatch()`は進行状態に加え、局面、直前打牌、局結果、編集履歴、公開アクション履歴を初期化する。親は自分を初期値とし、開始前に変更可能とする。

## 9. カンと追加ドラ

### 9.1 操作の入口

| 操作 | 登録入口 | 手番への影響 |
|---|---|---|
| 開始時点ですでに見えていたカン | 開始後の「局面補正」 | なし |
| 直前打牌への大明槓 | 「チー・ポン・カン」 | 鳴いた人へ移動 |
| 自分の暗槓・加槓 | 自分の番の「カン」 | 自分の嶺上牌待ち |
| 他家の暗槓・加槓 | 対象相手の番の「カン」 | 対象相手の打牌待ち |

局面補正で追加したカンは`MeldOrigin.setup`を維持し、役・待ち推定では発生時刻不明の公開副露として扱う。

### 9.2 訂正

- 開始後も`MeldOrigin.setup`の副露をタップして削除できる。
- 削除は手番や巡目を巻き戻さない。
- 対局中の通常カンは既存の取り消し条件を維持する。
- 依存する追加ドラを自動削除せず、利用者へ確認を促す。

### 9.3 追加ドラ

- 開始後の`DoraZone`またはアクションバーに「ドラ追加」を設ける。
- モーダルの牌パレットからドラ表示牌だけを1枚追加する。
- 河の現在入力先と手番は変更しない。
- カン確定直後は追加ドラの入力を案内する。
- 誤入力は`DoraZone`の対象牌をタップして削除する。
- 同一牌4枚制約と残数計算は既存`SituationEditor`を使う。

## 10. コンポーネント設計

### 10.1 SituationInputPage

`MatchInputFlow.started`と`RoundProgress.matchFinished`から`SetupInputLayout`、`StartedTableLayout`、`MatchFinishedView`を切り替える。進行規則をWidget内へ実装しない。

### 10.2 SetupInputLayout

開始前画面の骨格を担当する表示用Widget。表示専用の場・局・巡目、親、手牌、ドラ、入力対象、残数、`MatchSetupValidation`と各コールバックを受け取る。`GameSituation`を直接変更しない。

### 10.3 SetupTargetCard

手牌またはドラを常時表示し、選択状態、入力中ラベル、牌の直接削除を担当する。枚数制約は判定しない。

### 10.4 SetupTilePalette

既存の牌パレットを再利用し、選択中の入力対象へ牌タップを通知する。ドラ1枚制限をWidgetへ直接記述しない。

### 10.5 MatchSetupValidator

`GameSituation`、親位置、半荘終了状態から`MatchSetupValidation`を返す純粋なサービスとする。

### 10.6 MatchActionBar

開始後だけ取り消し、鳴き、カン、局終了、相手分析、設定に戻るを表示し、局面補正と追加ドラへも到達できるようにする。

### 10.7 DoraIndicatorPicker

開始後のドラ追加専用モーダル。河入力や手番と独立し、結果を`SituationEditor.add(InputTarget.doraIndicators, tile)`へ渡す。

## 11. アーキテクチャ

```text
presentation
  SituationInputPage          状態に応じた画面切り替え
  SetupInputLayout            開始前画面
  SetupTargetCard             手牌・最初のドラ
  SetupTilePalette            共通牌パレット
  MatchFinishedView           新しい対局
  MatchActionBar              開始後操作
  DoraIndicatorPicker         追加ドラ
application/domain
  MatchSetupValidator         開始条件と理由コード
existing domain
  GameSituation              手牌・ドラ・河・副露
  SituationEditor            追加・削除・枚数制約
  MatchInputFlow             開始・手番・カン・取り消し
  RoundProgress              場・局・巡目・新しい半荘
  RoundActionHistory         公開アクション履歴
```

依存方向は`presentation -> application/domain`とし、初期画面の都合を`GameSituation`へ持ち込まない。

## 12. 既存コードの変更方針

### 12.1 `lib/main.dart`

- `_buildSetupBody`を`SetupInputLayout`中心へ置き換える。
- `_RoundInput`を開始前から削除し、開始後の`CompactRoundStatus`は維持する。
- `DefaultTabController`と開始前`TabBar`を削除する。
- `_target`を開始前の手牌・ドラ選択だけに限定する。
- `_buildActionControls`を開始後操作中心に整理する。
- 開始前の`_showSetupKanDialog`を開始後の局面補正へ移す。

### 12.2 `RoundProgress`

- デフォルトの東1局・1巡目を維持する。
- UIから`selectRoundWind`、`selectKyoku`、`selectTurn`を呼ばない。
- `resetForNewMatch()`を追加する。
- `advanceRound`、`recordDraw`、`recordDiscard`は変更しない。

選択メソッドは将来の牌譜読込との互換性を考慮して直ちに削除せず、UIから切り離す。

### 12.3 `MatchInputFlow`

- `start()`は現在の自動進行値を維持する。
- `resetForNewMatch()`で進行・局面・履歴を一括初期化する。
- 開始可否を`MatchSetupValidator`と整合させる。
- 開始後のカン補正が通常手番を変更しないことを保証する。

### 12.4 `SituationEditor`

- 手牌の整列、4枚制限、直接削除を再利用する。
- 開始前のドラ1枚制限は専用入力で判定し、汎用ドラ追加は開始後に残す。
- `MeldOrigin.setup`を開始後にも訂正可能にする。

## 13. 状態不変条件

- 新しい半荘は必ず東1局・1巡目である。
- 次局準備で`start()`を押しても自動進行した場・局を失わない。
- 開始前のドラはちょうど1枚の場合だけ開始可能である。
- 開始後はカンに応じてドラを複数保持できる。
- 手牌は親なら最大14枚、子なら最大13枚で開始する。
- 同一牌は手牌、河、ドラ、副露の合計で4枚までである。
- 開始前の直接削除は進行、手番、公開履歴を変更しない。
- 開始後のカン補正は現在手番を変更しない。
- 通常カンの手番・嶺上牌制御は維持する。

## 14. エラーと案内

- 手牌が空: 「自分の手牌を入力してください」
- ドラが空: 「最初のドラ表示牌を1枚選んでください」
- ドラが2枚以上: 「開始前のドラ表示牌は1枚にしてください」
- 手牌上限超過: 親・子に応じた最大枚数を表示
- 5枚目の牌: 既存の4枚制限メッセージを表示
- カン補正後にドラが未追加: 開始後に非ブロッキングの案内を表示
- 半荘終了: 「新しい対局」以外の開始操作を無効にする

開始に必要な情報はSnackBarだけでなく画面内へ持続表示する。

## 15. テスト方針

### 15.1 ドメインテスト

- 初期値が東1局・1巡目・残り69回である。
- `resetForNewMatch()`が進行値と終了状態を初期化する。
- 次局準備からの`start()`が場・局を維持する。
- 南4局終了後に新しい対局を開始できる。
- 開始前ドラ0枚・1枚・2枚の検証結果が正しい。
- 親・子の手牌上限を検証する。
- 同一牌5枚の不正局面を検出する。
- カン補正の追加・削除が手番と巡目を変更しない。
- 追加ドラが4枚制限と残数へ反映される。

### 15.2 Widgetテスト

- 開始前に`kyokuSelector`、`turnSelector`、場風選択がない。
- 初回に東1局・1巡目が表示専用で表示される。
- 開始前に従来の`targetTab-*`がない。
- 手牌と最初のドラが同時に表示される。
- 初期入力対象が手牌である。
- 領域タップで入力対象と「入力中」が切り替わる。
- パレットから選択中の領域へ追加できる。
- 開始前の2枚目のドラを拒否する。
- 手牌とドラを直接タップして削除できる。
- 開始前に`setupKanButton`と「取り消し」がない。
- 手牌またはドラ不足時に開始できず理由が表示される。
- 条件成立後に親の河から開始する。
- 開始後に取り消し、カン補正、追加ドラへ到達できる。
- 次局準備で進行済みの場・局が表示される。
- 「新しい対局」で東1局へ戻る。

### 15.3 回帰テスト

- 手牌の標準順と親・子の枚数制限を維持する。
- 自分のツモ前打牌防止を維持する。
- 4打牌で巡目が進む。
- ツモ、ロン、流局で次局へ進む。
- チー、ポン、各カンと嶺上牌待ちを維持する。
- 取り消しと副露訂正を維持する。
- 危険率、相手分析、手出し・ツモ切り、リーチ入力を維持する。
- 開始後の卓レイアウトにオーバーフローがない。

## 16. アクセシビリティ

- 入力対象の選択状態をSemanticsへ設定する。
- 手牌とドラに「入力中」「未選択」などの読み上げラベルを付ける。
- 選択済み牌に「タップで削除」の説明を付ける。
- 開始ボタンが無効な理由を支援技術から読めるテキストで表示する。
- タップ領域は最低44論理ピクセルを目安に確保する。

## 17. 実装順序

1. `MatchSetupValidation`と`resetForNewMatch()`を追加する。
2. `SetupInputLayout`と2つの`SetupTargetCard`を追加する。
3. 開始前の局入力、タブ、カン、取り消しを除く。
4. ドラ1枚制限、直接削除、開始条件案内を接続する。
5. 開始後のカン補正と追加ドラを接続する。
6. 次局準備と半荘終了後の新しい対局を接続する。
7. 既存Widgetテストを新UIへ移行し、全回帰テストを実行する。

## 18. 完了条件

- Issue #9の受け入れ条件を満たす。
- 初期画面が親、手牌、最初のドラ、パレット、開始に整理されている。
- 場・局・巡目を編集せず東1局から新しい半荘を開始できる。
- 次局の自動進行値を保持したまま準備・開始できる。
- 開始前にタブ、カン、取り消しが表示されない。
- 開始後にカン、追加ドラ、取り消しを操作できる。
