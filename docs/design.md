# Maohjong 基本設計書

## 1. 目的

麻雀対局の局面を牌の見た目をタップして入力し、将来の危険牌・待ち・狙い役の分析へ渡せる、Android向けFlutterアプリを作る。初期版では、カメラ認識や外部AIには依存しない。

## 2. スコープ

### 初期版に含めるもの

- 牌パレットから萬子、筒子、索子、字牌をタップして選択する入力操作
- 入力先として、自分の手牌と自分・上家・対面・下家の河を切り替える操作
- 追加済み牌の削除と、最後の追加を戻す操作
- 牌の総数が4枚を超えない入力制約
- 手牌・河・ドラ表示牌・副露から算出した各牌の未確認枚数表示
- カンを考慮した複数のドラ表示牌の追加・削除
- 親の位置と開始時手牌を設定してから開始する対局入力フロー
- 親から打牌順に河の入力先を自動で切り替える操作
- 画面最下部に自分の手牌を常時表示し、自分の番は手牌から打牌を選ぶ操作
- 自分のツモ入力が完了するまで打牌を禁止する手番制御
- 手牌を萬子・筒子・索子・字牌の標準順へ自動整列
- 4人分の打牌による巡目の自動更新と、通常ツモの残り回数表示
- 残りツモ終了時の次局への自動移行
- 直前の打牌に対するチー・ポン・大明槓と、鳴いた人への手番変更
- 開始時点ですでに成立している明槓・暗槓・加槓の登録
- 自分の打牌可能な番における暗槓・加槓と、嶺上牌入力前の打牌防止
- 河とは分離したプレイヤー別の副露表示
- 取り消しによる直前の河への復帰と、入力済み牌を保持した設定の修正
- 分析機能が利用できる構造化した局面データの保持

### 初期版に含めないもの

- カメラによる牌認識
- 危険牌、待ち、役、点数の分析
- リーチなどの詳細局面入力
- 音声案内および外部AI API

## 3. 利用者操作

1. 場・局・巡目と、親の位置を選ぶ。
2. タブを使ってドラ表示牌と自分の手牌を入力する。局面開始時にすでにカンが成立している場合は、プレイヤー、牌、明槓・暗槓・加槓の種別を登録する。
3. 「開始」を押すと、親の河が入力先として表示される。
4. 相手の番は牌パレットから打牌を選ぶ。自分の通常手番は先に牌パレットからツモ牌を1枚追加し、その後に画面最下部の手牌をタップして打牌する。14枚で開始した親の初回とチー・ポン直後はツモ入力なしで打牌できる。
5. 打牌するたび、自分→下家→対面→上家の打牌順で次の河へ自動的に切り替わる。
6. 選択を間違えた場合は「取り消し」で直前の打牌を手牌へ戻し、その河へ戻る。開始前の設定を直す場合は「設定に戻る」を使う。
7. 直前の打牌を鳴く場合は「チー・ポン・カン」を押し、鳴いた人とチーの順子候補を選ぶ。鳴かれた牌は元の河から副露へ移り、次の打牌入力は鳴いた人から始まる。
8. 自分の打牌可能な番に暗槓・加槓候補がある場合は「カン」を押して選ぶ。確定後は嶺上牌を手牌へ追加するまで打牌できない。
9. 副露の選択を間違えた場合は副露をタップして取り消す。自分の番の暗槓・加槓は嶺上牌入力前だけ取り消せる。
10. 通常の山は配牌後69回として表示し、相手のツモは打牌入力時、自分のツモ・嶺上牌は牌選択時に1回減らす。4人分の打牌で巡目を1つ進める。
11. 残りツモが0になった局の最後の打牌後は、連荘なしとして親と局を進め、手牌・河・ドラ・副露を次局入力用に初期化する。
12. 後続版で、確定した局面を分析画面に渡す。

## 4. 画面設計

```text
┌──────────────────────────────┐
│ Maohjong 局面入力             │
│ 東1局・6巡目                  │
│ 残りツモ 49回                 │
│ 親の位置 [自分][下家][対面][上家] │
│ [手牌][自分][上家][対面][下家][ドラ]│
├──────────────────────────────┤
│ 選択中: 手牌                  │
│ [  ][  ][  ][  ][  ]          │
│ [取り消し]                    │
├──────────────────────────────┤
│ 牌を選ぶ                       │
│ 1萬 ... 9萬                    │
│ 1筒 ... 9筒                    │
│ 1索 ... 9索                    │
│ 東 南 西 北 白 發 中            │
├──────────────────────────────┤
│ 自分の手牌（常時表示・最大14枚を一列）│
│ 自分の副露 [チー 1萬2萬3萬]    │
└──────────────────────────────┘
```

牌は画像アセットを必須とせず、初期版では牌らしい枠と文字で描画する。牌パレットは端末幅に応じて自動調整し、萬子・筒子・索子をそれぞれ横一列に9枚表示する。自分の手牌はスクロール領域の外側に固定し、端末幅から牌幅を算出して最大14枚を横一列に収める。手牌は追加・復元時に萬子、筒子、索子、字牌の順、同種内は数字順へ自動整列する。副露は河や自分の非公開手牌と分けて表示する。開始前は選択中のタブだけを表示し、開始後は次に入力する河だけを表示する。後続版で牌画像へ差し替え可能な部品として実装する。

## 5. ドメイン設計

### Tile

牌を文字列ではなく列挙型で表す。萬子・筒子・索子の1から9、字牌の東南西北白發中の合計34種類を持つ。表示名や色はUI層で変換する。

### GameSituation

局面全体を表す将来用のモデル。初期版では以下を保持する。

- `hand`: 自分の手牌
- `ownRiver`: 自分の河
- `upperRiver`: 上家の河
- `acrossRiver`: 対面の河
- `lowerRiver`: 下家の河
- `doraIndicators`: 複数のドラ表示牌
- `melds`: プレイヤー、種別、公開牌、鳴き元、登録経路を持つ副露・カン

後続版で、リーチ状態、点数を追加する。

### 入力制約

- 同一種類の牌は局面全体で4枚まで
- 各牌の未確認枚数は、4枚から手牌・河・ドラ表示牌・副露の枚数を差し引いて算出
- 牌を追加できない場合は理由を画面に表示
- 自分が親なら開始時手牌は最大14枚、自分が子なら最大13枚
- 開始後の自分の番は、ツモ牌を含めて手牌を最大14枚まで保持可能
- 自分の手牌上限は、副露・カン1組につき3枚減らす
- 自分の通常手番はツモ牌を1枚入力するまで打牌不可とし、1手番に複数のツモ牌を追加できない
- 14枚で開始した親の初回とチー・ポン直後はツモ済みとして扱う
- 大明槓直後は嶺上牌のツモ入力が完了するまで打牌不可とする
- 自分の暗槓・加槓は打牌可能な番だけ選択でき、確定後は嶺上牌の入力が完了するまで打牌不可とする
- 開始前のカン登録は手番を変更せず、登録する4枚を手牌や河と重複させない
- チーは直前の打牌者の次の人だけ選択可能
- ポン・大明槓は直前の打牌者以外を選択可能
- 鳴かれた牌は河から削除し、3枚または4枚の副露として残数計算へ含める
- ドラ表示牌と自分の手牌が1枚以上入力されるまで「開始」は無効

### MatchInputFlow

開始前の条件、親の位置、副露数を考慮した自分の手牌上限、開始後の河入力順、ツモ待ち・打牌可能の状態を管理する。河の順序は自分→下家→対面→上家→自分とし、開始時だけ選択された親の河を先頭にする。自分の打牌はツモ完了後に手牌から自分の河へ移動し、取り消し時は元の手牌へ復元して入力先も自分の河へ戻す。鳴きが成立した場合は通常順を中断して鳴いた人へ入力先を変更し、その人の打牌後から通常順へ戻る。自分の暗槓・加槓後は河の順序を進めず嶺上牌待ちへ切り替える。

### RoundProgress

場風、局、巡目、残りツモ回数をUIから分離して管理する。通常の山は配牌完了時点で69回とし、指定巡目から開始する場合は `69 - (巡目 - 1) × 4` で概算する。4打牌ごとに巡目を進め、残りツモ0で東1局から東4局、南1局から南4局へ進行する。初期版には和了・流局結果や親の聴牌入力がないため連荘は行わず、南4局終了時は半荘終了とする。

## 6. アーキテクチャ

初期版はFlutter標準の`StatefulWidget`で局面入力を管理する。分析機能を追加する段階で、次の責務へ分離する。

```text
presentation
  SituationInputPage      画面表示と操作受付
  TilePalette             牌パレット表示
domain
  Tile / GameSituation    麻雀局面の純粋なデータ
  SituationEditor         入力制約と追加・削除・取り消し
  MatchInputFlow          親・手牌上限・河の入力順
  RoundProgress           局・巡目・残りツモ回数
application
  AnalyzeSituationUseCase 分析実行の窓口（後続版）
infrastructure
  CameraRecognizer        カメラ認識（後続版）
  SpeechService           読み上げ（後続版）
```

分析ロジックはUIやカメラに依存しない純粋なDartコードとして作る。これにより、手入力・カメラ入力・将来の牌譜読み込みのいずれからも同じ局面を分析できる。

## 7. テスト方針

- 牌タップで選択中の入力先に追加されるウィジェットテスト
- 入力先の切替、削除、取り消しのウィジェットテスト
- タブ切替時に選択中の牌領域だけを表示するテスト
- 数牌9枚が同じ行に収まるレイアウトテスト
- 5枚目の同種牌を拒否するテスト
- 複数ドラ表示牌の入力と残数更新のテスト
- 親の河から打牌順に入力先が循環するテスト
- 取り消し時に直前の河へ戻るテスト
- 固定表示した手牌から自分の打牌を選び、取り消すと手牌へ戻るテスト
- 自分の通常手番でツモ前の打牌を拒否し、ツモ後に許可するテスト
- 14枚の親初回、チー・ポン直後、大明槓直後のツモ要否を検証するテスト
- 手牌が追加・復元時に標準順へ自動整列されるテスト
- 通常ツモで残り回数が減り、4打牌で巡目が進むテスト
- 残りツモ0の最後の打牌後に次局へ進み、局面を初期化するテスト
- 指定巡目に応じて残りツモ回数を概算表示するテスト
- 360px幅で最大14枚の手牌が横一列に収まるテスト
- チーの候補と鳴ける人、ポン・大明槓後の入力順を検証するテスト
- 鳴かれた牌が河から副露へ移り、残数へ反映されるテスト
- 親・子に応じて自分の手牌を14枚・13枚までに制限するテスト
- 開始前に4人それぞれの明槓・暗槓・加槓を登録・訂正できるテスト
- 自分の副露数に応じて開始前・開始後の手牌上限が3枚ずつ減るテスト
- 自分の番に暗槓・加槓し、嶺上牌入力まで打牌を拒否するテスト
- 将来、分析ロジックはDartユニットテストで網羅する

## 8. 将来拡張

1. リーチ、点数の入力
2. シャンテン数、受け入れ牌、牌の残り枚数
3. 河と副露に基づく危険度・待ち・狙い役の確率推定と根拠表示
4. Android端末の音声読み上げ
5. カメラからの牌検出・分類を端末内モデルで実行
6. 任意で、説明文だけを無料枠APIまたはローカルモデルに委譲
