# Maohjong 対局開始後レイアウト 基本設計書

## 1. 目的

対局開始後の局面入力画面を、実際の麻雀卓に近い位置関係で常時把握できるレイアウトへ再構成する。

局情報と操作部品が卓の表示領域を圧迫している状態、および河・ドラ表示牌を切り替えないと確認できない状態を解消する。自分の手牌を画面最下部へ固定したまま、上家・対面・下家・自分の河、ドラ表示牌、副露、現在の入力対象を少ない視線移動で確認できるUIを目指す。

## 2. 対象範囲

### 2.1 含めるもの

- 対局開始後専用の卓レイアウト
- 局、巡目、親位置、残りツモ回数のコンパクト表示
- 上家、対面、下家、自分の河の同時表示
- 複数のドラ表示牌の常時表示
- 各プレイヤーのポン、チー、カンの常時表示
- 現在の入力対象と入力案内の強調表示
- 牌パレットに対して約50%を基準とする卓上牌のレスポンシブ表示
- 画面最下部に固定した自分の手牌と危険率表示
- 小さい牌に対する操作領域とアクセシビリティの確保
- 既存の入力、訂正、副露、守備分析、局進行操作の維持

### 2.2 含めないもの

- 開始前の場、局、巡目、親、手牌、ドラ、カン設定フローの全面変更
- 上家または下家の牌画像の回転
- 点数計算、親の連荘、リーチ入力の追加
- 危険牌の判定ルール変更
- カメラ認識または音声案内
- 牌画像アセットへの置き換え

## 3. 設計原則

### 3.1 情報の優先順位

対局開始後は、次の順で表示領域を確保する。

1. 自分の固定手牌
2. 現在の入力対象と操作案内
3. 4人分の河、ドラ表示牌、副露
4. 牌パレット
5. 局情報と補助操作

固定手牌と卓は画面に残し、端末高が不足する場合は牌パレット内部だけをスクロールさせる。画面全体をスクロールして河や手牌が見えなくなる構成にはしない。

### 3.2 位置関係

自分から見た卓上の位置を基準とする。

- 上家：左
- 対面：上
- 下家：右
- 自分：下
- ドラ表示牌：中央

ただし、牌画像は全プレイヤーとも回転させない。上家と下家の河・副露も、読みやすい横向きの牌を左から右へ並べる。

### 3.3 表示と操作の分離

牌の見た目はパレットの約50%まで縮小できるが、タップ可能範囲まで同じ比率には縮小しない。河・ドラ・副露の領域全体を選択可能にし、牌単体を訂正できる箇所には視覚サイズより広いヒット領域とセマンティクスラベルを設定する。

## 4. 画面状態

### 4.1 開始前

既存の設定画面を維持する。

- 場、局、巡目を選択する
- 親の位置を選択する
- タブで手牌、河、ドラ表示牌を切り替える
- 開始時点のカンを登録する
- 自分の手牌は画面最下部にも表示する

Issue 5では開始前のタブ構成を廃止しない。開始後レイアウトとの責務を分け、既存の設定操作を後退させない。

### 4.2 対局開始後

- 手牌タブを含む入力先タブを表示しない
- 左上にコンパクトな局情報を表示する
- 卓領域に全プレイヤーの河、ドラ、副露を同時表示する
- 自分の河は固定手牌の直上に配置する
- 現在の入力対象は、該当するプレイヤー領域の枠線、背景色、ラベルで強調する
- 自分のツモ待ちまたは打牌待ちは、固定手牌付近の案内でも示す
- 牌パレット、取り消し、鳴き、カン、局終了、守備分析、設定に戻る操作を維持する

## 5. レイアウト設計

### 5.1 縦画面の基本構成

```text
┌────────────────────────────────┐
│ 東1局 6巡  親:対面              │  左上のコンパクト局情報
│ 残りツモ 49                     │
├────────────────────────────────┤
│          対面の河               │
│          対面の副露             │
│                                │
│ 上家の河     ドラ表示牌    下家の河 │
│ 上家の副露                下家の副露 │
│                                │
│          自分の河               │
│          自分の副露             │
├────────────────────────────────┤
│ 次: 下家の河を選択              │  入力状態・操作ボタン
│ [戻す] [鳴き] [カン] [局終了]    │
├────────────────────────────────┤
│ 牌を選ぶ                         │
│ 1萬 … 9萬                       │  高さ不足時はこの領域だけスクロール
│ 1筒 … 9筒                       │
│ 1索 … 9索                       │
│ 東 南 西 北 白 發 中             │
├────────────────────────────────┤
│ 自分の手牌 13/14  タップして打牌  │  Scaffold下部へ固定
│ [牌][牌][牌] … [牌]              │
└────────────────────────────────┘
```

### 5.2 高さの配分

`Scaffold`の本文を画面全体の`ListView`にはせず、開始後は`Column`と`Expanded`で領域を分割する。

1. `CompactRoundStatus`: 内容に応じた最小高さ
2. `TableBoard`: 利用可能高のうち優先して確保する可変領域
3. `MatchActionBar`: 48 logical pixels以上の固定高さ。幅不足時も1行を維持する
4. `TilePalettePanel`: 残り高さを使用し、必要な場合だけ内部スクロール
5. `PersistentHand`: `bottomNavigationBar`で最下部へ固定

キーボード入力はないため、通常時はソフトウェアキーボードによる高さ変動を考慮しない。セーフエリア、表示倍率、端末下部のシステム領域は考慮する。

### 5.3 卓領域

`TableBoard`は3行3列の論理領域として配置する。物理実装は`GridView`へ限定せず、`Column`と`Row`または`CustomMultiChildLayout`を選択できる。

| 行 | 左 | 中央 | 右 |
|---|---|---|---|
| 上 | 空き | 対面 | 空き |
| 中 | 上家 | ドラ表示牌 | 下家 |
| 下 | 空き | 自分 | 空き |

各プレイヤー領域は次を持つ。

- プレイヤー名
- 河
- 副露
- 現在の入力対象を示す状態

上家と下家も領域内では横書きとし、牌を回転させない。領域幅が狭い場合は河を複数行へ折り返す。河は捨て順を維持し、1行の上限は標準的な河に合わせて6枚を基本とする。ただし、実際の列数は利用可能幅と最低牌幅から算出する。

### 5.4 牌サイズ

牌パレットの牌サイズを基準値`paletteTileWidth`、`paletteTileHeight`とし、卓上表示は次を基準とする。

```text
tableTileWidth  = paletteTileWidth  × 0.5
tableTileHeight = paletteTileHeight × 0.5
```

実際の描画サイズは`LayoutBuilder`で利用可能幅と牌数から算出し、領域外へはみ出す場合は基準値より小さくできる。拡大する場合もパレットより目立たない上限を設ける。

- 河、副露、ドラには共通の卓上牌メトリクスを使う
- 固定手牌は既存どおり最大14枚を横一列へ収める独自メトリクスを使う
- 危険率は固定手牌だけに表示し、卓上牌には重複表示しない
- 文字や枠が判別できない極端な縮小を避け、必要なら河を折り返す

## 6. コンポーネント設計

### 6.1 SituationInputPage

開始前と開始後の画面構成を切り替える最上位画面とする。局面編集、対局進行、守備分析の既存状態を保持するが、卓の物理配置計算は担当しない。

### 6.2 SetupInputLayout

開始前の既存入力UIを担当する。局・巡目、親、入力先タブ、開始時点のカン、開始ボタンを表示する。既存実装を段階的に抽出し、Issue 5では挙動を変更しない。

Issue 9では開始前画面を簡略化するため、この記述を[対局開始前画面の簡略化 基本設計書](setup_screen_simplification_design.md)で置き換える。開始後の`StartedTableLayout`は引き続き本書を正とする。

### 6.3 StartedTableLayout

対局開始後の画面骨格を担当する。次のデータとコールバックを受け取る表示用Widgetとする。

- `GameSituation`
- `RoundProgress`
- 親位置
- 現在の河
- ツモ待ち・打牌待ち状態
- 取り消し、河の訂正、副露訂正、各操作ボタンのコールバック

対局順、手牌上限、ツモ要否などのルールをWidget内へ再実装しない。

### 6.4 CompactRoundStatus

局、巡目、親位置、残りツモ回数を1～2行で左寄せ表示する。色だけに依存せず、短い文字ラベルを併記する。

表示例：`東1局 6巡 / 親: 対面 / 残りツモ 49`

開始後は表示専用とし、変更操作は「設定に戻る」から行う。

### 6.5 TableBoard

上家、対面、下家、自分、ドラの位置を決定する。端末サイズから各領域と卓上牌のメトリクスを算出し、個々の河や副露の内容は`PlayerZone`へ委譲する。

### 6.6 PlayerZone

1人分の河と副露を表示する。`InputTarget`を受け取り、`GameSituation.tilesFor`と`meldsFor`で表示対象を取得する。現在の入力対象の場合は選択状態を表示する。

牌の削除や副露の訂正は既存コールバックへ委譲し、ドメインデータを直接変更しない。

### 6.7 DoraZone

複数のドラ表示牌を中央へ表示する。ドラが0枚になる状態は既存の開始条件により開始直後には発生しないが、表示Widgetは空状態も安全に扱う。

### 6.8 MatchActionBar

取り消し、チー・ポン・カン、自分のカン、局終了、守備分析、設定に戻るへ到達できるようにする。利用可否は既存の`MatchInputFlow`と`SituationEditor`の判定結果を使う。

Issue #11では、複数行へ折り返す従来方針を[対局中コンパクトアクションバー 基本設計書](compact_match_action_bar_design.md)で置き換える。主要操作は固定高さの1行へ表示し、補助操作は「その他」メニューへまとめる。

### 6.9 TilePalettePanel

既存の34種類の牌と残数表示を維持する。牌は数牌9枚を横一列へ収める。開始後の画面高が不足する場合はこの領域だけを縦スクロール可能にし、卓と固定手牌は動かさない。

### 6.10 PersistentHand

既存どおり最下部へ固定し、最大14枚を横一列へ収める。開始後は手牌タブを持たず、この領域だけを手牌の表示・打牌操作・危険率確認に使う。

## 7. 状態と操作

### 7.1 入力対象の表示

`MatchInputFlow.currentRiver`を唯一の入力順の根拠とする。開始後の卓表示は常に全員分を描画し、現在の入力対象だけを次の方法で強調する。

- 領域の枠線を太くする
- テーマの`primaryContainer`相当の背景色を使う
- `入力中`ラベルを表示する
- `matchInputStatus`と同じ案内文を操作部へ表示する

自分の番でツモが必要な場合は河ではなく牌パレットと固定手牌付近を強調し、ツモ前に打牌できない既存制約を維持する。

### 7.2 河の訂正

表示中の河牌をタップしたときは既存の削除処理を呼ぶ。縮小表示により誤操作が増えないよう、牌間隔とヒット領域を描画サイズとは別に設計する。現在の入力対象以外の河も訂正できる既存仕様を維持する。

### 7.3 副露の訂正

副露は所有者の`PlayerZone`内で河と区別して表示する。タップ時は既存の`removeMeld`処理を呼び、操作可能条件と河への復元規則は変更しない。

### 7.4 ドラ表示牌

開始後は常に中央へ表示する。局面の確認を目的とし、開始後の追加・削除可否は既存の進行規則を変更しない。修正が必要な場合は「設定に戻る」を使用する。

## 8. レスポンシブ設計

### 8.1 基準端末

少なくとも次の論理画面サイズでレイアウトを検証する。

- 360 × 640: 小型のAndroid縦画面
- 412 × 915: 一般的なAndroid縦画面

表示倍率が大きい場合は局情報内の折り返しと牌パレット内部スクロールを許可する。操作ボタンは折り返さず、[対局中コンパクトアクションバー 基本設計書](compact_match_action_bar_design.md)に従って主要操作と「その他」メニューへ分ける。卓上の主要情報と固定手牌は可能な限り残す。

### 8.2 オーバーフロー対策

- 固定ピクセル幅だけで牌サイズを決めない
- `LayoutBuilder`の制約から列数と牌サイズを算出する
- 河と副露は`Wrap`または同等の折り返しを使う
- 長いラベルは省略または短い表記へ切り替える
- 操作ボタンは固定高さの1行とし、補助操作を「その他」メニューへ移す
- 牌パレット以外の領域へ無制限なスクロールを持たせない

## 9. アクセシビリティ

- 入力対象は色だけでなく枠線と文字で示す
- 牌に`Semantics`で牌名、所有者、河または副露、捨て順を付与する
- 小さい牌のヒット領域は描画サイズより広くする
- 危険率は数値と長押し説明を維持する
- 文字倍率を上げた場合も操作ボタンが欠けず、内部スクロールで到達できるようにする
- 訂正操作は誤タップ時に既存の取り消し操作で回復できる状態を維持する

## 10. アーキテクチャ

```text
presentation
  SituationInputPage       開始前・開始後レイアウトの切り替え
  SetupInputLayout         開始前の設定とタブ入力
  StartedTableLayout       開始後の画面骨格
  CompactRoundStatus       局・巡目・親・残りツモ表示
  TableBoard               卓上の位置とサイズ計算
  PlayerZone               1人分の河・副露・入力状態
  DoraZone                 ドラ表示牌
  MatchActionBar           対局中の操作
  TilePalettePanel         牌選択と残数表示
  PersistentHand           固定手牌・打牌・危険率
domain
  GameSituation            手牌・河・ドラ・副露
  MatchInputFlow           入力順・ツモ待ち・打牌可否
  RoundProgress            局・巡目・残りツモ
  SituationEditor          牌・副露の編集と制約
```

Issue 5はプレゼンテーション層の再構成を主目的とする。`GameSituation`、`MatchInputFlow`、`RoundProgress`、`SituationEditor`の規則は既存のまま利用し、画面配置の都合をドメインモデルへ持ち込まない。

## 11. テスト方針

### 11.1 Widgetテスト

- 開始前は既存の入力先タブが表示される
- 開始後は手牌を含む入力先タブが表示されない
- 開始後は上家、対面、下家、自分の河、ドラ、固定手牌が同時に存在する
- 対面が上、上家が左、下家が右、自分が下の位置関係になる
- 全プレイヤーの牌が回転せず横向きで表示される
- 現在の河だけに入力中表示がある
- 打牌後に強調対象が次の河へ移る
- 自分のツモ待ちと打牌待ちが固定手牌付近へ表示される
- 河、副露、ドラの描画幅がパレット牌の約50%を基準に算出される
- 360 × 640と412 × 915でRenderFlex overflowが発生しない
- 卓と固定手牌を動かさず、必要な牌パレット項目へ内部スクロールで到達できる
- 各プレイヤーの副露が所有者の領域に表示される
- 河牌と副露をタップして既存の訂正処理を実行できる
- 取り消し、鳴き、カン、局終了、守備分析、設定に戻る操作へ到達できる
- 固定手牌の通常タップ、危険率表示、長押し理由表示が維持される

位置関係のテストでは、ラベル文字列だけでなく安定したKeyと`tester.getRect`を使う。オフスクリーン要素を探すだけのテストにせず、主要領域が同一画面内へ配置されていることを確認する。

### 11.2 回帰テスト

- 牌の全体4枚制限と残数計算
- 親から始まる打牌順と4打牌ごとの巡目更新
- 自分のツモ前打牌防止
- チー、ポン、カン後の手番と嶺上牌待ち
- 取り消しと副露取り消し
- ツモ、ロン、流局後の次局遷移
- 危険率と理由表示

UIの再配置により既存のドメインテストを変更しない。既存Widgetテストが単一表示領域を前提としている場合は、挙動の期待値を維持したまま新しい固定領域のKeyへ更新する。

## 13. 実装順序

1. 開始前と開始後のレイアウト分岐を抽出する
2. コンパクト局情報を追加する
3. `TableBoard`と空の各プレイヤー領域を配置する
4. 既存の河、副露、ドラ表示を各領域へ接続する
5. 現在の入力対象と案内表示を接続する
6. 牌パレットと操作部を高さ制約へ対応させる
7. 固定手牌の既存操作と危険率を接続する
8. レスポンシブWidgetテストと既存回帰テストを通す
9. 実機またはエミュレータで縦画面の視認性とタップ操作を確認する

## 14. 完了条件

- Issue 5の受け入れ条件を満たす
- 開始後の主要局面をタブ切り替えなしで同時確認できる
- 小型端末でも卓と固定手牌を原則スクロールせず確認できる
- 既存の入力・訂正・進行・副露・守備分析機能が後退しない
- 新規・変更したDartコードに日本語Dartdocがある
- `dart format lib test`が成功する
- `dart analyze lib test`が成功する
- `flutter test --no-pub`が成功する
- `git diff --check`で問題がない
- エミュレータまたは実機で主要領域の表示と操作を確認する
