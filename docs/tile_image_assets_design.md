# Maohjong 牌画像アセット 基本設計書

## 1. 目的

文字と枠で描画している牌を、実際の麻雀牌に近いCC0画像へ置き換える。牌選択パレット、固定手牌、河、ドラ表示牌、副露、分析画面で同じ牌画像を再利用し、局面を短時間で読み取れるUIにする。

画像化後も、既存の入力操作、危険率、残数、選択状態、レスポンシブ表示、アクセシビリティを維持する。アプリ実行時の画像取得や有料サービスへの依存は設けない。

## 2. 対象Issue

- GitHub Issue #13「牌表示をCC0の麻雀牌画像へ置き換える」

## 3. 対象範囲

### 3.1 含めるもの

- 現在の`Tile`が持つ34種類に対応する牌画像
- 牌選択パレット
- 開始前および開始後の自分の手牌
- 自分、上家、対面、下家の河
- ドラ表示牌
- ポン、チー、明槓、暗槓、加槓の表示
- 守備分析および相手意図分析で、牌そのものを視覚表示する部品
- 画像上の選択中、無効、残数、危険率などの状態表示
- 画像を読み込めない場合の文字表示へのフォールバック
- 素材の出典、ライセンス、取得時点を記録する文書

### 3.2 含めないもの

- 赤5萬、赤5筒、赤5索を区別するドメインモデルと入力制約
- 牌画像テーマの切り替え
- 画像の回転、立体的な卓上表現、アニメーション
- カメラ認識用の学習画像または教師データへの転用
- 説明文中の「1萬」など、文章として必要な牌名の画像化
- 危険牌、待ち、狙い役の分析ルール変更

## 4. 素材とライセンス

### 4.1 採用素材

- 名称: `FluffyStuff/riichi-mahjong-tiles`
- 配布元: https://github.com/FluffyStuff/riichi-mahjong-tiles
- 使用セット: `Regular`
- 形式: SVG
- ライセンス: CC0 1.0 / Public Domain
- ライセンス原文: https://github.com/FluffyStuff/riichi-mahjong-tiles/blob/master/LICENSE.md

実装時は特定のコミットを指定して素材を取得し、そのコミットIDを`SOURCE.md`へ記録する。外部URLを実行時に参照せず、使用する34ファイルとライセンス文書をリポジトリへ同梱する。

### 4.2 配置

```text
assets/
  images/
    mahjong_tiles/
      regular/
        Man1.svg ... Man9.svg
        Pin1.svg ... Pin9.svg
        Sou1.svg ... Sou9.svg
        Ton.svg Nan.svg Shaa.svg Pei.svg
        Haku.svg Hatsu.svg Chun.svg
      LICENSE.md
      SOURCE.md
```

`pubspec.yaml`には`assets/images/mahjong_tiles/`をアセットとして登録する。SVG表示には無料の`flutter_svg`パッケージを利用する。バージョンは実装時点でプロジェクトのFlutter/Dart SDKと互換性が確認できる安定版に固定し、アプリ実行時の通信は行わない。

### 4.3 牌とファイルの対応

| `Tile` | ファイル | `Tile` | ファイル |
| --- | --- | --- | --- |
| `m1`～`m9` | `Man1.svg`～`Man9.svg` | `p1`～`p9` | `Pin1.svg`～`Pin9.svg` |
| `s1`～`s9` | `Sou1.svg`～`Sou9.svg` | `east` | `Ton.svg` |
| `south` | `Nan.svg` | `west` | `Shaa.svg` |
| `north` | `Pei.svg` | `white` | `Haku.svg` |
| `green` | `Hatsu.svg` | `red` | `Chun.svg` |

対応は列挙値の文字列連結で推測せず、全34種を列挙した一つの定数マップで管理する。未対応の列挙値が追加された場合はテストで検出する。

## 5. 表示コンポーネント設計

### 5.1 責務分離

```text
domain
  Tile                         牌の種類。画像パスを持たない

presentation
  TileAssetPath                Tileから同梱アセットへの対応を返す
  MahjongTileFace              牌画像と文字フォールバックを描画する
  既存の入力・卓・分析Widget    操作、状態枠、バッジ、Semanticsを担当する
```

ドメイン層はFlutterアセットやSVGライブラリへ依存させない。`tileLabel()`は削除せず、Semantics、ツールチップ、理由文、エラー時表示に継続利用する。

### 5.2 `MahjongTileFace`

共通Widgetは少なくとも次を受け取る。

- `tile`: 表示する`Tile`
- `width`、`height`: 親レイアウトが決めた表示領域
- `fit`: 原則`BoxFit.contain`
- `excludeFromSemantics`: 外側の操作WidgetがSemanticsを持つ場合は`true`

共通Widgetは牌面の描画だけを担当する。タップ、長押し、削除、危険分析の起動などの操作は持たせない。これにより同じ画像を操作可能な牌と参照専用の牌で再利用できる。

SVGの読込に失敗した場合は、現在の牌らしい枠と`tileLabel(tile)`を表示し、画面全体を例外終了させない。デバッグ時に原因を追跡できる一方、ユーザーへファイルパスは表示しない。

### 5.3 状態表示

画像そのものは加工せず、既存Widgetが前面または外枠に状態を重ねる。

- 選択中: アクセント色の枠と選択Semantics
- 無効: 画像全体の不透明度を下げ、タップを無効化
- 残数: 既存の残数ラベルまたはバッジを維持
- 危険率: 固定手牌上の数値バッジを維持
- 現在の入力対象: 牌単体ではなくプレイヤー領域または入力カードを強調
- 訂正可能: 外側の`InkWell`と既存Keyを維持

危険率や残数の文字は牌の模様と重なっても読めるよう、十分なコントラストを持つ単色背景のバッジ上へ表示する。

## 6. 画面別適用方針

### 6.1 牌選択パレット

- 萬子、筒子、索子は現在どおり各9枚を横一列へ収める
- 字牌は現在のレスポンシブ配置を維持する
- 画像の下または隅に残数を表示する
- 4枚見えている牌は無効表示とし、既存の追加拒否を維持する
- 安定した`palette-${tile.name}`のKeyとタップ領域を維持する

### 6.2 自分の手牌

- 画面幅へ最大14枚が収まる既存の幅計算を維持する
- 画像は指定された枠内で縦横比を維持し、はみ出させない
- 開始前のタップ削除、開始後のタップ打牌、長押し理由表示を維持する
- 危険率バッジは画像より前面に表示する

### 6.3 卓上表示

- 河、ドラ、副露は牌パレットの約50%という既存寸法を維持する
- 上家と下家を含め、画像を回転しない
- 小さい牌画像とは別に、既存の訂正可能領域をタップ領域として確保する
- 暗槓の伏せ牌表現は本Issueでは追加せず、現在保持している`Tile`を同じ牌面画像で表示する

### 6.4 分析画面とダイアログ

- 一覧や候補の先頭で牌そのものを示す表示は画像化する
- スコア、確信度、残数、待ち形、理由文はテキストのまま維持する
- 牌名が文中に含まれる箇所は`tileLabel()`を維持する
- チー、ポン、カンの牌選択候補にも共通画像を利用する

## 7. レスポンシブ・アクセシビリティ

- `360 × 640`を最小確認サイズとし、文字倍率1.5でもRenderFlex overflowを発生させない
- SVGは親から渡された有限サイズの範囲で描画し、画像の元サイズでレイアウトを決めない
- 小型の卓上牌でも操作領域は既存設計の44論理ピクセル目安を維持する
- 操作可能な牌の外側に「1萬、残り3枚、タップして追加」などのSemanticsを設定する
- 外側がSemanticsを持つ場合、SVG内部のSemanticsを除外して二重読み上げを防ぐ
- 色だけで選択、無効、危険度を伝えず、枠、数値、ラベルを併用する

## 8. エラー処理

- アセット対応漏れは開発時のテストで検出する
- SVGの解析・読込失敗時は文字牌へフォールバックする
- 1枚の画像エラーで他の牌や局面入力を操作不能にしない
- ライセンス文書がない状態を完了としない
- 素材取得元のファイルを無関係に一括同梱せず、使用対象だけを管理する

## 9. テスト方針

### 9.1 単体テスト

- `Tile.values`の34種すべてに空でない一意のアセットパスがある
- 各パスのアセットを`rootBundle`から読み込める
- 牌とファイル名の対応が萬子、筒子、索子、字牌で正しい

### 9.2 Widgetテスト

- 代表牌ではなく34種すべてが画像Widgetとして描画できる
- 牌パレットのタップ、無効状態、残数表示を維持する
- 開始前の手牌削除と開始後の打牌を維持する
- 固定手牌の危険率表示と長押し理由表示を維持する
- 河、ドラ、副露の訂正操作と既存Keyを維持する
- カン後のドラ表示牌選択を画像化しても進行が維持される
- 相手分析の候補選択と理由表示を維持する
- SVG読込失敗時に文字牌へフォールバックする
- 360 × 640、文字倍率1.5で開始前・開始後にoverflowがない

既存テストで牌名の`Text`を直接探索している箇所は、表示文字への依存をやめ、既存Key、Semantics、操作結果で検証する。理由文など本来テキストである表示の検証は維持する。

### 9.3 品質確認

- `dart format lib test`
- `flutter analyze --no-pub`
- `flutter test --no-pub`
- `git diff --check`
- エミュレーターまたは実機で開始前、対局中、分析画面の視認性と操作を確認

## 10. 実装順序

1. 素材の取得コミットとライセンスを確認する
2. 使用する34ファイル、`LICENSE.md`、`SOURCE.md`を配置する
3. `pubspec.yaml`へアセットとSVG依存を追加する
4. `TileAssetPath`と`MahjongTileFace`を実装する
5. 牌パレットと固定手牌を共通画像へ置き換える
6. 河、ドラ、副露を置き換える
7. 分析画面と牌選択ダイアログを置き換える
8. 既存の文字依存テストを操作・Key・Semantics中心へ更新する
9. 全テストとレスポンシブ確認を行う
10. 実機またはエミュレーターで視認性を確認する

## 11. 完了条件

- Issue #13の受け入れ条件を満たす
- 34種すべてが正しいCC0牌画像で表示される
- 素材の出典、取得コミット、ライセンスがリポジトリ内で確認できる
- 実行時のネットワークアクセスや有料サービスを必要としない
- 既存の入力、訂正、進行、危険率、長押し、分析機能に回帰がない
- 小型画面および文字拡大時にoverflowがない
- 新規・変更したDartコードに日本語Dartdocがある
- 静的解析、全テスト、差分検査が成功する
- エミュレーターまたは実機で画像表示と主要操作を確認する
